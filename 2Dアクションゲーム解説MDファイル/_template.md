# 記入のガイドライン

> このセクションはコピー後に削除する。

## 書き方の原則

**1. 結論を先に書く**
「〜だからです」より「〜です。理由は〜」の順。

**2. 「なぜそう書いたか」を必ず残す**
コードの動作は読めば分かる。**設計判断の理由は書かないと失われる。**

**2-2. 質問は原文のまま残す**
要約すると「何につまずいたのか」という文脈が消える。
特に**推測を含んだ質問は、どこがズレていたかが次回の教材になる。**
言い回しそのものが、初心者がどう誤解しやすいかの記録になる。

**3. 参加者が間違える箇所を太字にする**
後で読み返したとき、太字だけ拾えば地雷が分かる状態にする。

**4. 言い換えをストックする**
同じ説明を何度もするので、伝わった言い方は記録しておく。

**5. 共通知識は `00_共通の基礎知識.md` へ**
複数のスクリプトに登場する話題（`GetComponent` など）はそちらに書き、
個別ファイルからは参照するだけにする。同じ説明の重複を防ぐ。

## ファイル命名規則

```
README.md              ← 全体の索引
00_共通の基礎知識.md
01_PlayerController.md
02_PlayerHealth.md
03_EnemyPatrol.md
04_敵の撃破処理.md      ← EnemyHealth / EnemyAttack / StompZone
05_Goal.md
06_DamageZone.md
07_SceneLoader.md      ← SceneLoader / SceneButton
08_HpUI.md
09_CameraFollow.md
10_スコア機能.md        ← ScoreManager / Coin / ScoreUI
```

番号は理解の順番。依存関係の少ないものから並べる。

**連携して動くスクリプトは1ファイルにまとめる。**
単体で読んでも意味が分からないものを分けると、かえって理解しにくくなる。

新しく追加する場合は末尾に番号を続ける。
