# 共通の基礎知識

各スクリプトの解説で繰り返し出てくる内容をここにまとめる。
個別のスクリプト解説から参照すること。

---

## 1. コードの読み方

### `.` は「〜の」と読む

C# の基本構造。`.` でつながっているものは「〜の」と読めば意味が通る。

| 書き方 | 読み方 |
|---|---|
| `Physics2D.OverlapCircle` | 物理2Dの、円の重なり調べ |
| `spriteRenderer.flipX` | スプライトレンダラーの、X反転 |
| `rb.linearVelocity` | リジッドボディの、速度 |

### 命令名は英語のまま分解する

Unity の命令は英単語を並べただけの名前が多い。分からない命令が出てきたら、まず名前を分解して読む。

```
Physics2D + Overlap + Circle
2D物理     重なり    円
```

これはプロも実際にやっている読み方。**「知らない命令が出てきたら名前を疑う」** という習慣を教えると、以降の学習が速くなる。

### `.` の前が大文字か小文字か

| | 何を指すか | 例 |
|---|---|---|
| 大文字始まり | **道具箱**（世界に1つしかない共通の機能） | `Physics2D.` `Input.` `Mathf.` `Debug.` |
| 小文字始まり | **自分で用意した変数**（たくさんある中の1つ） | `rb.` `spriteRenderer.` `animator.` |

道具箱は特定する必要がないのでそのまま書ける。
変数は「どれの話か」を指す必要があるので、事前に用意しておく必要がある。

## 2. GetComponent と変数の関係

### 3点セットで覚える

```csharp
private Rigidbody2D rb;                 // ① 箱を用意する（中身は空）

void Awake()
{
    rb = GetComponent<Rigidbody2D>();   // ② 中身を入れる
}

void FixedUpdate()
{
    rb.linearVelocity = ...;            // ③ 使う
}
```

この3つが揃って初めて動く。どれか1つでも欠けると動かない。

### `rb` は自分で決めた名前

`rb` は Unity の命令ではなく、ただの変数名（rigidbody の略）。
宣言・代入・使用の3箇所で一致していれば何でもよい。

```csharp
private Rigidbody2D playerBody;         // これでも動く
playerBody = GetComponent<Rigidbody2D>();
playerBody.linearVelocity = ...;
```

**参加者は `rb` を Unity の予約語だと思い込むことが多い**ので、最初に伝えておく。

### 変数は「実体」ではなく「案内札」

`rb` の中に Rigidbody2D のコピーが入っているわけではない。
「Player の Rigidbody2D はこれだよ」という案内札が入っている。

だから `rb.linearVelocity = ...` と書くと、本物の値が本当に変わる。

### 毎回 GetComponent してはいけない

```csharp
GetComponent<Rigidbody2D>().linearVelocity = ...;   // 動くがNG
```

`GetComponent` は「探す」処理。`FixedUpdate` は1秒に50回呼ばれるので、
敵が10体いれば1秒に500回の探索になる。

**`Awake()` で1回だけ探して保管する**のが Unity の基本。

## 3. Update と FixedUpdate の使い分け

### 違い

| | Update | FixedUpdate |
|---|---|---|
| 呼ばれるタイミング | 1コマ描くたび | 一定時間ごと（標準1秒50回） |
| 回数 | PC性能でバラバラ | 常に一定 |
| 向いている処理 | 入力を拾う、見た目を変える | Rigidbody を動かす |

### 判断基準

**コードに `Rigidbody` か `Physics2D` という単語が出てきたら `FixedUpdate`。**

初心者でも即座に判断できるので、この基準で教えるとよい。

| Update に書く | FixedUpdate に書く |
|---|---|
| `Input.〜`（入力の取得） | `rb.linearVelocity`（速度） |
| `spriteRenderer.flipX`（見た目） | `rb.AddForce()`（力を加える） |
| `animator.SetBool()`（アニメ） | `Physics2D.〜`（当たり判定の検査） |

### たとえ方

`Update` は「目で見て判断する」、`FixedUpdate` は「体を動かす」。
目は速く動かせても、体はリズムを守る。

## 4. private / public / SerializeField

### private と public

| | 意味 | 使いどころ |
|---|---|---|
| `private` | 自分専用。他のスクリプトから触れない | **基本はこちら** |
| `public` | 他のスクリプトから触れる | 外から呼んでほしいものだけ |

**原則：基本は `private` にして、外から呼ぶ必要があるものだけ `public` にする。**
何でも `public` にすると、どこから書き換えられているか分からなくなる。

### `[SerializeField]` の役割

`private` のままインスペクターに表示させるための記述。

```csharp
[SerializeField] private float moveSpeed = 6f;
```

`public` にしてもインスペクターに出るが、それだと他のスクリプトから
勝手に書き換えられる。**「自分専用だけど調整はしたい」を両立させるもの。**

### カプセル化という考え方

**変数は隠して、操作はメソッド経由にする。そうすれば「やり忘れ」が起きない。**

```csharp
private int currentHp;                    // 隠す
public void TakeDamage(int damage) { }    // 操作はメソッドで
public int CurrentHp => currentHp;        // 読むだけなら許可
```

`currentHp` を `public` にすると、外から `currentHp = -5` と書けてしまい、
HPがマイナスなのに死亡処理が走らない、という壊れ方をする。

**「勝手に触られると壊れる値は、隠してメソッド経由にする」**

## 5. 引数とフィールドの違い

```csharp
private bool canControl = true;     // フィールド（ずっと残る）

public void SetControl(bool enable) // 引数（メソッドが終わると消える）
{
    canControl = enable;            // 写し取る
}
```

| | 引数（`enable`） | フィールド（`canControl`） |
|---|---|---|
| 寿命 | メソッドが終わると消える | ゲーム中ずっと残る |
| 誰が決める | 呼び出した側が渡す | このスクリプトが保持する |

引数は「外から届いた手紙」、フィールドは「その内容を書き写した掲示板」。
`Update()` から毎フレーム参照するには、掲示板の方が必要になる。

### 引数とフィールドは名前を変える

```csharp
public void SetControl(bool canControl)
{
    canControl = canControl;   // NG：どちらも引数を指してしまう
}
```

C# は近い方（引数）を優先するため、フィールドは何も変わらない。
**エラーが出ないのに動かない**という最悪の形のバグになる。

引数には `enable` `value` `newValue` など別の名前を付ける。

## 6. インスペクターとコードの対応

**インスペクターに並んでいる項目は、ほぼ全てコードから触れる。**

| コード | インスペクターの項目 | 型 |
|---|---|---|
| `spriteRenderer.flipX` | Sprite Renderer の Flip X | `bool` |
| `spriteRenderer.color` | Color | `Color` |
| `spriteRenderer.enabled` | 左上のチェックボックス | `bool` |
| `spriteRenderer.sortingOrder` | Order in Layer | `int` |
| `rb.linearVelocity` | （実行中のみ）Velocity | `Vector2` |

再生中にインスペクターを手で操作させると、コードと画面の対応が一発で伝わる。

## 7. 設計の指針：どこまでコードに書くか

| 種類 | 扱い | 例 |
|---|---|---|
| 常に同じもの | コードに直接書く | 重力の向き |
| **素材や状況で変わるもの** | **インスペクターに出す** | 速度、HP、絵の向き |

**「後で変えたくなりそうな値は、外に出しておく」**

素材が変わるたびにコードを直す設計は筋が悪い。
チェックボックス1つで対応できるようにしておけば、コードを読まずに解決できる。

## 8. 必ず聞かれる質問と回答例

**Q. `void` って何？**
A. 「この処理は結果を返さない」という印。計算結果を渡す必要がないときに使う。

**Q. `private` と `public` の違いは？**
A. `private` は自分専用、`public` は他のスクリプトから触れる。基本は `private`。

**Q. `[SerializeField]` を付けると何が変わるの？**
A. `private` のままインスペクターに表示される。値を調整できるようになる。

**Q. `GetComponent` は何をしてるの？**
A. 同じオブジェクトに付いている別の部品を探して持ってくる。持ってきた後は、
その名前で呼べば操作できる。

**Q. `!= null` は何？**
A. 「空っぽではない」という意味。見つからなかった場合に処理を止めるための確認。

**Q. `!` は何？**
A. 「反対にする」記号。`!true` は `false` になる。
